# Domerium — описание сущностей базы данных

**Лабораторная работа №1, пункт 5.** Описание 10 таблиц для MVP. Типы приведены для PostgreSQL. Имена таблиц и полей записаны в `snake_case`.

## Условные обозначения

- **PK** — первичный ключ; **FK** — внешний ключ; **UQ** — уникальность.
- **NOT NULL** — значение обязательно; **NULL** — поле может быть пустым.
- **CHECK** — допустимые значения или условие для одной записи.
- `UUID` используется для идентификаторов пользователя и домашней группы; соответствующие внешние ключи имеют тот же тип.
- `BIGINT GENERATED ALWAYS AS IDENTITY` используется для остальных основных идентификаторов; `role.id` имеет тип `SMALLINT`.
- `TIMESTAMPTZ` — дата и время создания или изменения; `DATE` — календарная дата без времени.

## 1. `users` — пользователь

Учетная запись для входа в приложение. Хранит также системный статус администратора; групповые роли задаются через участие в группе.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `UUID` | PK, генерируется при создании пользователя | Идентификатор пользователя |
| `email` | `VARCHAR(254)` | NOT NULL, UQ | Адрес для входа; перед сохранением приводится к единому регистру |
| `password_hash` | `TEXT` | NOT NULL | Хеш пароля, не исходный пароль |
| `display_name` | `VARCHAR(120)` | NOT NULL | Имя для отображения |
| `system_role` | `VARCHAR(16)` | NOT NULL, DEFAULT `USER`, CHECK: `USER` или `ADMIN` | Роль на уровне всего приложения |
| `status` | `VARCHAR(16)` | NOT NULL, DEFAULT `ACTIVE`, CHECK: `ACTIVE`, `BLOCKED`, `DELETED` | Доступность учетной записи |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `CURRENT_TIMESTAMP` | Время регистрации |
| `deleted_at` | `TIMESTAMPTZ` | NULL | Время логического удаления учетной записи |

Связи: 1:1 с `user_settings`; 1:M с `membership`, `transaction`, `group_event`, `event_participation` и `audit_log`. Учетная запись может быть создателем `home_group`. При удалении учетная запись получает статус `DELETED`, вход блокируется, а ссылки на исторические записи сохраняются.

Для согласованности статуса и времени удаления предусмотрен CHECK: `deleted_at` заполнено тогда и только тогда, когда `status = 'DELETED'`.

## 2. `user_settings` — личные настройки

Настройки отделены от данных для входа, так как они управляют отображением календаря конкретным пользователем.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `user_id` | `UUID` | PK, FK → `users.id` | Владелец настроек; PK гарантирует не более одного набора на пользователя |
| `time_zone` | `VARCHAR(64)` | NOT NULL, DEFAULT `UTC` | Часовой пояс отображения событий |
| `date_format` | `VARCHAR(16)` | NOT NULL, DEFAULT `DD.MM.YYYY`, CHECK по разрешенным форматам | Формат даты в интерфейсе |

Связь: `users` 1:1 `user_settings`. База гарантирует **не более одного** набора; создание строки настроек вместе с пользователем обеспечивает наличие набора у каждого зарегистрированного человека.

## 3. `home_group` — домашняя группа

Закрытое пространство участников. Основная валюта применяется ко всем операциям группы в первой версии.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `UUID` | PK, генерируется при создании группы | Идентификатор группы |
| `name` | `VARCHAR(120)` | NOT NULL | Название группы |
| `currency_code` | `CHAR(3)` | NOT NULL, CHECK: три заглавные латинские буквы | Основная валюта учета |
| `created_by_user_id` | `UUID` | NOT NULL, FK → `users.id` | Создатель группы |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `CURRENT_TIMESTAMP` | Время создания |

Связи: 1:M с `membership`, `transaction_category`, `transaction`, `group_event` и `audit_log`; M:1 с `users` по создателю. Владелец определяется активным членством с ролью `OWNER`, поэтому создатель и текущий владелец могут быть разными пользователями.

## 4. `role` — роль внутри группы

Справочник групповых ролей. На старте используются `OWNER` и `MEMBER`; системный администратор задается отдельно в `users`.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `SMALLINT` | PK | Идентификатор роли |
| `code` | `VARCHAR(20)` | NOT NULL, UQ; для MVP `OWNER` или `MEMBER` | Стабильный код роли |
| `name` | `VARCHAR(60)` | NOT NULL | Название для отображения |
| `can_manage_members` | `BOOLEAN` | NOT NULL | Право приглашать, исключать и менять роли участников |
| `can_manage_finances` | `BOOLEAN` | NOT NULL | Право создавать и изменять финансовые операции |
| `can_manage_events` | `BOOLEAN` | NOT NULL | Право создавать и изменять события |

Связь: `role` 1:M `membership`.

## 5. `membership` — членство в группе

Соединяет пользователя и домашнюю группу. Содержит дополнительные сведения о роли и приглашении, поэтому является полноценной сущностью, а не простой таблицей из двух ключей.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `BIGINT` | PK, identity | Идентификатор членства |
| `user_id` | `UUID` | NOT NULL, FK → `users.id` | Пользователь |
| `home_group_id` | `UUID` | NOT NULL, FK → `home_group.id` | Группа |
| `role_id` | `SMALLINT` | NOT NULL, FK → `role.id` | Роль пользователя именно в этой группе |
| `status` | `VARCHAR(16)` | NOT NULL, CHECK: `PENDING`, `ACTIVE`, `REJECTED`, `LEFT` | Состояние приглашения или участия |
| `invited_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `CURRENT_TIMESTAMP` | Время создания приглашения или членства |
| `joined_at` | `TIMESTAMPTZ` | NULL; для `ACTIVE` обязательно | Время принятия приглашения |

Ограничение **UQ (`user_id`, `home_group_id`)** разрешает только одну запись на пару «пользователь — группа». При повторном приглашении после отказа обновляется прежнее членство; изменения фиксируются в `audit_log`. Связи: M:1 с `users`, `home_group` и `role`. Через эту таблицу реализуется `users` M:N `home_group`.

## 6. `transaction_category` — категория операции

Категории принадлежат группе: соседи и семья могут использовать разные названия для своих доходов и расходов.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `BIGINT` | PK, identity | Идентификатор категории |
| `home_group_id` | `UUID` | NOT NULL, FK → `home_group.id` | Группа, владеющая категорией |
| `name` | `VARCHAR(80)` | NOT NULL | Название категории |
| `kind` | `VARCHAR(8)` | NOT NULL, CHECK: `INCOME` или `EXPENSE` | Для какого вида операций используется категория |

Ограничение **UQ (`home_group_id`, `kind`, `name`)** не допускает одинаковых названий категорий одного вида внутри группы. Связи: `home_group` 1:M `transaction_category`; `transaction_category` 1:M `transaction`. Категория выбранной операции должна принадлежать той же группе и соответствовать виду операции.

Для составного FK из `transaction` дополнительно предусматривается UQ (`id`, `home_group_id`, `kind`); первичный ключ `id` при этом сохраняется.

## 7. `transaction` — финансовая операция

Единая сущность для фактических и разовых запланированных доходов и расходов. План не учитывается в фактическом итоге до подтверждения.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `BIGINT` | PK, identity | Идентификатор операции |
| `home_group_id` | `UUID` | NOT NULL, FK → `home_group.id` | Группа, в финансах которой отражена операция |
| `created_by_user_id` | `UUID` | NOT NULL, FK → `users.id` | Автор записи |
| `category_id` | `BIGINT` | NOT NULL, FK → `transaction_category.id` | Категория |
| `kind` | `VARCHAR(8)` | NOT NULL, CHECK: `INCOME` или `EXPENSE` | Доход либо расход |
| `status` | `VARCHAR(16)` | NOT NULL, CHECK: `PLANNED`, `COMPLETED`, `CANCELLED` | План, факт либо отмена |
| `amount` | `NUMERIC(14,2)` | NOT NULL, CHECK `amount > 0` | Плановая сумма; после подтверждения — фактическая |
| `planned_date` | `DATE` | NULL; для `PLANNED` обязательно | Когда операция ожидается |
| `actual_date` | `DATE` | NULL; для `COMPLETED` обязательно | Когда операция произошла |
| `description` | `TEXT` | NULL | Пояснение |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `CURRENT_TIMESTAMP` | Время создания записи |

Связи: M:1 с `home_group`, `users` и `transaction_category`. Для `PLANNED` `actual_date` отсутствует; для `COMPLETED` она обязательна. Для отмененной операции `actual_date` не заполняется. При подтверждении можно уточнить `amount`; исходное изменение останется в журнале действий. Категория принадлежит той же группе и имеет тот же `kind`, что и операция.

## 8. `group_event` — событие группы

Событие видно в календаре домашней группы; оно может быть отменено без потери истории.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `BIGINT` | PK, identity | Идентификатор события |
| `home_group_id` | `UUID` | NOT NULL, FK → `home_group.id` | Группа события |
| `created_by_user_id` | `UUID` | NOT NULL, FK → `users.id` | Создатель |
| `title` | `VARCHAR(160)` | NOT NULL | Название |
| `description` | `TEXT` | NULL | Подробности |
| `starts_at` | `TIMESTAMPTZ` | NOT NULL | Начало события |
| `ends_at` | `TIMESTAMPTZ` | NULL, CHECK: позднее `starts_at` | Окончание, если известно |
| `status` | `VARCHAR(16)` | NOT NULL, DEFAULT `SCHEDULED`, CHECK: `SCHEDULED` или `CANCELLED` | Актуальность события |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `CURRENT_TIMESTAMP` | Время создания |

Связи: M:1 с `home_group` и `users`; 1:M с `event_participation`. При показе время преобразуется в часовой пояс пользователя из `user_settings`.

## 9. `event_participation` — приглашение на событие

Позволяет отличать приглашенного человека от человека, подтвердившего участие. Содержит ответ и время приглашения, поэтому учитывается как самостоятельная сущность.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `BIGINT` | PK, identity | Идентификатор приглашения |
| `group_event_id` | `BIGINT` | NOT NULL, FK → `group_event.id` | Событие |
| `user_id` | `UUID` | NOT NULL, FK → `users.id` | Приглашенный пользователь |
| `status` | `VARCHAR(16)` | NOT NULL, DEFAULT `PENDING`, CHECK: `PENDING`, `ACCEPTED`, `DECLINED` | Ответ на приглашение |
| `invited_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `CURRENT_TIMESTAMP` | Время приглашения |
| `responded_at` | `TIMESTAMPTZ` | NULL; для ответа обязательно | Время ответа |

Ограничение **UQ (`group_event_id`, `user_id`)** запрещает дублирующее приглашение на одно событие. Связи: M:1 с `group_event` и `users`. Через эту таблицу реализуется `users` M:N `group_event`. Приглашать разрешено только действующих участников группы события.

При статусе `PENDING` время ответа пустое; при `ACCEPTED` или `DECLINED` оно должно быть заполнено.

## 10. `audit_log` — журнал действий

Автоматически сохраняет значимые действия в группе и действия администратора с учетными записями. Пользователи не редактируют его вручную.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | `BIGINT` | PK, identity | Идентификатор записи |
| `home_group_id` | `UUID` | NULL, FK → `home_group.id` | Группа; для системного действия может отсутствовать |
| `actor_user_id` | `UUID` | NOT NULL, FK → `users.id` | Исполнитель действия |
| `action` | `VARCHAR(40)` | NOT NULL | Тип действия: создание, изменение, отмена и т. п. |
| `entity_type` | `VARCHAR(40)` | NOT NULL | Тип измененного объекта |
| `entity_id` | `TEXT` | NOT NULL | Идентификатор измененного объекта: UUID или число в текстовом представлении |
| `occurred_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `CURRENT_TIMESTAMP` | Время действия |

Связи: M:1 с `users`; необязательная M:1 с `home_group`. Пара `entity_type` + `entity_id` описывает объект действия, но не является обычным FK сразу на несколько таблиц. Записи журнала не изменяются и не удаляются пользователями.
